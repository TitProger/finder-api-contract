# Changelog Finder API

Единственный источник HTTP. Версия — git-тег. `info.version` в `openapi.yaml` совпадает с тегом без префикса `v`.

## v0.16.0

Telegram-бот и тарифы free/unlimited убраны из API. Канал связи завода `ContactChannel.TELEGRAM` остаётся.

- Из `Inquiry` и `CreateInquiryRequest` убран `telegramUserId`. Создание админской заявки требует только `text`
- Из `InquiryStatus` убран `LIMIT_EXCEEDED`
- `photoUrls` — идентификаторы файлов хранилища или непрозрачные строки, не Telegram `file_id`
- Бот в контракте больше не участвует

Тег `v0.16.0` ставится вместе с коммитом этого каталога. Пока коммита нет, `contract:sync` берёт рабочее дерево.

## v0.15.0

Калькуляторы ставок. Логистику считает код по книге владельца, не модель. Досье и очередь ресерча не менялись.

- `GET/POST /admin/rates`, `GET|PATCH|DELETE /admin/rates/{id}` — справочник ставок; книга по умолчанию пустая
- `POST /rates/quote` — детерминированный расчёт; без ставок `{ "status": "unavailable", "reason": "rates_not_configured" }`
- `POST /rates/margin` — оценка маржи с расходами и оговоркой, что это не факт прибыли
- Вес с `origin=inferred` в quote не принимается (400)
- Тег `rates`

Тег `v0.15.0` ставится вместе с коммитом этого каталога. Пока коммита нет, `contract:sync` берёт рабочее дерево.

## v0.14.0

Каноническое утверждённое досье и live-кэш. Optimal card эволюционирует сюда: заявка, товар, поставщик и оффер остаются разными сущностями. Очередь ресерча и калькуляторы не менялись.

- `POST/GET/PATCH /admin/dossiers`, `POST .../reviews`, `POST .../publish` — админ подтверждает категорию/оффер/поставщика и публикует живое досье со сроком перепроверки
- `GET /dossiers/{id}/report` и `GET /client/inquiries/{id}/report` — безопасный клиентский отчёт без контактов завода, сырой закупки и внутренних заметок
- Повторный похожий запрос может обслуживаться из живого досье (`SERVED_FROM_DATABASE`, matchKind exact|similar)
- `GET /products/{id}` явно описан как безопасный отчёт карточки истории

Тег `v0.14.0` ставится вместе с коммитом этого каталога. Пока коммита нет, `contract:sync` берёт рабочее дерево.

## v0.13.0

Очередь ресерча на Postgres и честный статус заявки. Redis не добавлялся. Живой webhook Grok не обещается.

- `GET /client/inquiries/{id}` — публичный статус заявки с `clientStatus` / `clientStatusLabel` без процентов
- `GET /admin/research/runs/{runId}/evidence` — сырые свидетельства для админа (URL, цитата, время, статус площадки)
- В статусах заявки — `QUEUED_RESEARCH`
- `POST /research/ingest` — повтор с тем же payload sha256 идемпотентен
- Тег `research` описывает очередь, ingest и свидетельства

Тег `v0.13.0` ставится вместе с коммитом этого каталога. Пока коммита нет, `contract:sync` берёт рабочее дерево.

- `GET /admin/taxonomy/nodes`, `PATCH /admin/taxonomy/nodes/{nodeId}` — поиск и правка узла по админскому токену
- В клиентской заявке `taxonomyNodeId` — id узла дерева; свободная строка категории истиной не является

## v0.11.0

- Недостающие поля `profileJson` остаются `null`

Публичное чтение истории поиска и карточки товара. Админский токен эти ручки не требуют. Старые ручки заявок, категорий и ресерча не менялись.

## v0.8.0

Первый тег этого репозитория. Ручки health, категорий, заявок, оптимальных карточек и ресерча перенесены без смены смысла.

Скелет, которого не было в дереве: общие параметры `page`, `limit`, `sort`, `id` и вынос `securitySchemes` в отдельный файл. Текущие операции на эти параметры не переведены.

`nullable: true` записан как OpenAPI 3.1: `type: [..., 'null']` или `anyOf` с `null`. Набор полей и ручек тот же.

Убраны вход по логину и обновление сессии. Админские ручки принимают только статический Bearer-токен.

- Удалены `POST /admin/login` и `POST /admin/refresh`
- `POST /inquiries` и `GET /inquiries/{id}` тоже принимают только статический Bearer-токен
- Исход классификации: `no_match` вместо прежней заглушки. Совпадение по похожести больше не описывается
